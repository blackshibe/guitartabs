# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server (typically port 5173)
- `npm run build` — `tsc -b` type-check then Vite build; run this to verify changes
- `npm run lint` — oxlint

`npm test` — vitest; unit tests live in `src/lib/__tests__/` (reducer/history, clipboard, songOps, tunings, instruments, exportText, youtube, LZW, storage migrations). Pure-logic only — no component/DOM tests. A first-run `WelcomeDialog` (intro + controls, `tab-editor:welcomed` localStorage flag) shows once; its shortcut list is shared with `ShortcutHelp` via `lib/shortcuts.ts`.

## Architecture

Single-page guitar tab editor: React 19 + TypeScript, Vite, Tailwind CSS v4 (via `@tailwindcss/vite` plugin — no tailwind.config; global styles in `src/index.css`, which force-disables `border-radius` everywhere by design).

Song content lives in a single reducer (`lib/songReducer.ts`) driven from `src/App.tsx` via `useReducer(historyReducer)`. `App.tsx` is a composition root only — each UI concern is a custom hook in `src/hooks/` owning its own state, refs, and effects: `useToast`, `usePlayback` (scheduler + playhead + `tracksRef`), `useSelection` (selection rect, `gridRef`, document-level deselect), `useClipboard` (cell/section copy-paste, OS-clipboard mirror), `useGridEditing` (the grid keydown map + global undo/redo listener), `useSongLibrary` (IndexedDB hydration/`hydrated`, autosave, import conflicts, export/import). Abbreviated identifiers are banned in App/hooks and in shared type fields — `CellPos`/`Playhead` use `measure`/`column`/`stringIndex`, `Rect` uses `startColumn`/`endColumn`/`startString`/`endString`, and reducer actions use full-word fields (`set-cell` takes `measure`/`column`/`stringIndex`); the reducer's internal mirror math keeps short index locals by design. `SongState` carries `updatedAt` (stale between saves; save paths stamp `Date.now()`). Deployment: `vite.config.ts` sets `base: "./"` and `.github/workflows/deploy.yml` publishes `dist/` to GitHub Pages on push to main (repo Settings → Pages → Source: "GitHub Actions", one-time). Child components in `src/components/` are purely presentational and receive state + callbacks as props. `lib/youtube.ts` declares the `window.YT` global (typed `YouTubePlayer`/`YouTubeNamespace`) so nothing casts `window`. Pure logic lives in `src/lib/`:

- `types.ts` — core model: a `Song` has `tracks` and `sections`, plus an optional `youtube` reference-video anchor and an optional `measureNotes` (string array, one free-text annotation per measure, shared across tracks — not per-track). A `Track` has a `tuning` (array of `{noteIndex, octave}`, row 0 = top string as drawn), `measures`, and an optional `loops` (sectionId → loop-unit bars, live), and an optional `volume` (0–1 synth mix gain, absent = 1). Stems are NOT track-based — `Song.stems` is a list of `SongStem` audio layers (base64 ogg/mp3 saved inside the song JSON, numeric `nextId()` id, own `volume`) that play alongside the synth from measure 0 at song tempo; a stem needs no tabbed counterpart (e.g. drums, or the untabbed rest of a song) — that shape was chosen by explicit request over per-track stems. There is no vocal/lyric track kind — every track is the strings model; that variant was removed by explicit request in favor of `measureNotes`. A `Measure` is 8 columns (`COLS_PER_MEASURE`) of per-string values (`string | null`); a harmonic cell is stored as `"<7>"` (`lib/harmonics.ts`: toggled with the H key, drawn as `◇7` in the grid, exported verbatim in ASCII, and played at the natural-harmonic node pitch above the open string — 12→+12, 7→+19, 5→+24, 4/9→+28, others octave). `Section.linkTo` (live) points a section at the root section it mirrors.
- `lib/songReducer.ts` — the only structural writer: tagged-union `SongAction` cases plus the undo `historyReducer` wrapper (past/present/future, cap 100). Guarded no-ops return `state` identically. `coalesceKey` merges consecutive same-target edits (typing "1","2" → one undo step); keep keys narrow and per-field. `resolveMirrorSet` is the closure that fans a single-cell edit out across both live features at once — cross-section links (`mirrorMeasures`, whole-track, every linked copy) and a track's own loop unit (`trackLoopMirror`, that track only) — so `set-cell`/`clear-range`/`paste-cells` never touch linked/looped content directly. `set-measure-note` uses `mirrorMeasures` alone (no per-track loop mirroring — annotations aren't track-scoped) so a linked section's annotation stays in sync too. `link-section` requires equal span between the two sections (a guarded no-op otherwise) and resolves to one ultimate root id (no indirection chains); `set-track-loop` writes a `unit < span` and immediately mirrors bars `unit..span-1` from `0..unit-1`. `delete-section`/`delete-measure` clean up now-orphaned `linkTo`/`loops`/`measureNotes` references rather than leaving them dangling; `insertBlankAt`/`insertSectionBlock` splice `measureNotes` in lockstep with `measureCount` on every measure-count-changing action.
- `lib/songOps.ts` — pure helpers: `sectionRangesFor`, `dedupeSections`, `measuresEqual`, and `insertMeasuresIntoTrack`/`deleteMeasuresFromTrack` — the only splice sites for a track's timeline.
- `lib/clipboard.ts` — `Rect` (global-column cell rectangle), `CellClipboard`/`SectionClipboard` payloads, OS-clipboard JSON round-trip (`parsePayload`; internal clipboard state is authoritative, OS mirror is best-effort). `SectionClipboard.measureNotes` carries per-offset annotations along with a copied section, same as `comment`/`trackComments`.
- `lib/exportText.ts` — ASCII export; folds repeats per track back to `xN` (consecutive identical sections merge, and a section that is k repetitions of a smaller unit prints the unit once — `findRepeatUnit`). Works unmodified with live loops/links since mirrored bars are real, equal content — the fold is inferred from equality, not from the `loops`/`linkTo` fields. Does not currently print `measureNotes`.
- `lib/instruments.ts` — measure/track factory (`makeTrack`), `MEASURES_PER_LINE` (4) grid wrapping, id counter (call `advanceIdCounter` after loading persisted songs so new ids don't collide).
- `lib/tunings.ts` — MIDI/note-name conversion plus the tuning generator: presets are not a flat list but instrument × type × root (`TUNING_TYPES`, `rootsFor`, `tuningMidisFor` — Standard/Drop derived by transposing the E-standard shape down, Open from authored per-root shapes; guitar and bass). `defaultTuning()` is E standard guitar.
- `lib/audio.ts` — Web Audio playback (lazy singleton `AudioContext`): a short decaying triangle wave (`playNote(freq, time, duration?, volume?)`), and timeline-aligned layer playback (`startStem`, keyed by stem id or track id — same `nextId` space, no collisions) used by both `Song.stems` and `Track.backing` (an uploaded mp3/ogg of that track's real part: plays from measure 0 at song tempo and mutes the track's synth notes; a Karplus-Strong guitar synth and then a pitch-shifted note sampler were both built and rejected — the user wanted the recorded part, not an instrument imitation). `decodeAudio` caches buffers by payload object identity (pre-warmed by an `App` effect so first play is on time); `stopStems` generation-kills late decodes; `setStemVolume` retargets gain live.
- `lib/youtube.ts` — YouTube IFrame API loader (lazy, cached promise), video-id parsing (`extractVideoId`), and the anchor-measure ↔ video-seconds conversion (`videoSecondsForCol`, constant tempo from `bpm`) that keeps the reference video locked to the tab timeline.
- `lib/sectionColors.ts` — `tieColor(colorIndex)`: muted per-group colors for linked-section tie marks, lit for the dark ground; unrelated to playback or export.
- `lib/storage.ts` — song library in IndexedDB (`tab-editor`/`songs`, keyPath `id`; every library function is async) because localStorage's ~5MB quota can't hold stem audio — a legacy localStorage library is migrated into IDB once on first open and the old key removed. Only tiny metadata stays in localStorage: last-opened song id and a manual library order (`moveSong` swaps neighbors and pins the order; `listSongs` puts manually-ordered ids first, never-moved songs after them newest-first). `migrateSong` migrates the legacy global `Section.repeat` (writes out duplicate bars, seeds an equivalent per-track `loops` entry) and legacy track audio (`migrateLegacyTrackAudio`: the short-lived per-track `stem` becomes `backing` — same semantics — while the `sample`/`instrument` experiments are stripped); `parseSongsJson` runs `migrateSong` at the import border so old files are stored normalized — `linkTo` and `loops` are live, reducer-driven fields now, not legacy shapes; `resyncLiveFeatures` just self-heals them on load (re-mirrors from source) without stripping either field. Song ids are `crypto.randomUUID()`; export is whole-library or per-song (`exportSong`) as minified JSON compressed with LZW (`lib/lzw.ts`: variable-width 9–16-bit codes, dict frozen when full, "TABZ"+version header; `.tabz` files), and import (`parseSongsFile`) accepts both compressed and legacy plain-JSON exports, split from `importSongs` so `App` can prompt (ImportConflictDialog) before overwriting ids that already exist — new ids import immediately, conflicting ids only if checked. `App` starts on a blank song and hydrates the library + last-opened song from IDB in a mount effect, rendering `GhostScreen` (a pulsing skeleton of the real layout) until both resolve. Range sliders are restyled globally in `index.css` (hairline track, 3px accent caret thumb — the "position is a line" motif).

Key invariants:

- Every track has exactly `measureCount` measures; every column has exactly `tuning.length` entries; `measureNotes` (when present) stays parallel to `measureCount`. All structural edits go through reducer cases, which route through the `songOps` splice helpers.
- Sections are markers (`startMeasure`) over the shared measure timeline; ranges are derived (`sectionRangesFor`). The first section (sorted) must start at measure 0, section starts must be unique and in range — measure deletion re-clamps/dedupes them. A section can link to another of the same span (SectionNav's "link"/"unlink" controls); every write to a linked group's content applies to all copies via `resolveMirrorSet`. A track can independently loop a sub-range of any section (TabGrid's per-section "loop" control); looped bars are real, always-materialized content, not hidden/ghost measures — the export's repeat-folding picks them up for free.
- Selection is a `RangeSelection` `{anchor, focus}` rect over global columns (`m * COLS_PER_MEASURE + c`) crossing measure boundaries; keyboard edits target `focus`. The grid's keydown handler must ignore events originating from `INPUT`/`TEXTAREA` (section name/notes/measure-annotation fields live inside the grid). The document-level mousedown listener deselects outside `[data-grid]`/`[data-keep-selection]` — the sticky utility bar, transport bar, and reference-video widget all carry `data-keep-selection` so they don't clear an active selection. The focused cell renders as a caret (`border-l-2 border-l-accent`), not a boxed outline — see DESIGN.md.
- Playback mixes all tracks over the real timeline; `Song.stems` start once at playback start (offset to the from-step) and play alongside the synth, and the reference video gets a once-a-second drift check against the audio clock (re-seek past 0.3s off) so buffering can't detune it from the tab. All mixing lives in the corner Sound panel (`YoutubeSync.tsx`), not in `TrackTabs` (which shows only the tuning readout, printed low→high by `tuningLabel`): the panel holds the reference video (attach/remove, sync-here, a sync readout row showing the anchor — `sync · #N ↔ m:ss.mmm` — with ±50ms nudge buttons that adjust `anchorSeconds`, player volume persisted at `tab-editor:yt-volume`), one row per tab track (backing-audio upload/remove plus volume — the scheduler reads volume/backing through `tracksRef` so changes apply mid-playback, and `setTrackVolume` also retargets a playing backing's gain), and one row per stem (volume live via `setStemVolume` during playback, remove), a single keyed "Add source" button that opens a chooser (YouTube video — only when none attached — or MP3/OGG stem; the two never have separate add buttons), and a master-volume slider in the panel header (persisted at `tab-editor:master-volume`, driving `setMasterVolume` — every synth note, stem, and backing routes through one master GainNode in `lib/audio.ts`). `applySong`'s `advanceIdCounter` call includes stem ids. The on-screen grid shows only the active track (switched via `TrackTabs`), never multiple tracks stacked at once. Clicking a cell during playback jumps playback to that cell (App wraps the selection handler; shift-clicks extend selection without jumping), and `startPlayback` kills any previous scheduler/stems before starting so mid-play restarts (scrub, jump) never stack two tick loops. Playback uses a lookahead scheduler in `usePlayback`'s `startPlayback` (the standard Web Audio pattern), not a naive setTimeout-per-note loop: a `tick()` on a ~25ms timer schedules any notes falling within a 150ms lookahead window onto the real audio clock (`playNote(freq, exactTime)`), so JS event-loop jitter (React renders, GC) can only delay how far ahead we schedule, never the audio itself; the visual playhead is updated via a separate `setTimeout` matched to each note's real scheduled time (the overlay glides with `transition: left <stepDurationMs>ms linear` — paced to the tempo via TabGrid's `stepDurationMs` prop, replacing the fixed 150ms ease that stuttered at slow tempos), tracked in `visualTimeoutsRef` and cleared alongside the main loop on stop. `TransportBar` (fixed to the viewport bottom, `z-50` — the bar is a stacking context, so its shortcut-help popover can never exceed the bar's own z; at `z-30` the Sound panel (`z-40`) painted over the popover) carries both playback (play/stop/BPM/scrub) and the add-measure/add-section actions in a three-column grid layout (`grid-cols-[1fr_auto_1fr]`, not a centered flex row) so the play button stays genuinely centered regardless of side-group width — the row is full-viewport-width (no `max-w` column) so +Measure/+Section hug the left screen edge and BPM/help the right, by explicit request; there is no standalone Clear action (redundant with the sidebar's "+ New"). `TrackTabs` + `SectionNav` are wrapped `sticky top-0` in `App.tsx` so the track switcher and section jump stay reachable while a long tab's grid scrolls underneath — `TabGrid`'s section and line wrappers carry `scroll-mt-[190px]` so jump-to-section and the playhead auto-scroll land below the pinned bar, and the score body carries `mt-4` so normal scrolling always leaves a gap under the pinned bar too. Blocked actions toast instead of silently no-opping; destructive ops are undo-covered (`Ctrl+Z`), so only track/section/library delete confirm.
- `YoutubeSyncPanel` (`components/YoutubeSync.tsx`) is a floating widget, `fixed` to the bottom-right corner at `md:` and up (`bottom-16 right-4` — offset above the fixed transport bar so they never overlap); below `md` it drops to an in-flow block. `Song.youtube` holds one anchor point (`anchorMeasure`/`anchorSeconds`); playback seeks/plays the video from the computed time and pauses it on stop — the video does not independently drive the tab's clock.

Visual system (palette, type, component language) is recorded in `DESIGN.md` — read it before touching any component's styling; it documents the committed dark-plate, single-family-Inter world and the load-bearing structural patterns (sticky utility bar, fixed bottom transport, corner video widget, translating playhead rule, the caret-style focus/playhead language, the lucide-react icon set themed through `components/Icons.tsx`) so they don't drift back into ad hoc chrome or a reintroduced serif face.
